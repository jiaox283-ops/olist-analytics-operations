## 2. 做法

### 2.1 写在 `sql/05_business_analysis.sql` 里的 12 条查询

一条查询回答一个问题，用注释 `-- Q01` 到 `-- Q12` 分隔：

| 查询 | 内容 | 用到的写法 |
|---|---|---|
| Q01 | 规模、金额、客单价、缺失计数、时间范围 | 条件聚合 |
| Q02 | 状态结构及占比 | `GROUP BY` + 占比 |
| Q03 | 延迟率、配送天数、评分及各自有效分母 | 多个有效标记分别计数 |
| Q04 | 月度订单量、金额、运费、客单价 | `DATE_FORMAT` 按月分组 |
| Q05 | 相邻月份订单、金额、客单价环比 | `LAG` 窗口函数 |
| Q06 | 按购买月份的交付完成率与延迟率 | 分组聚合 |
| Q07 | 类别金额占比、销量、组内订单数 | `SUM() OVER()` 算占比与累计占比 |
| Q08 | 类别运费 / 商品金额比 | 只用商品与运费都完整的配对订单 |
| Q09 | 客户州金额、占比、订单量、客单价 | 窗口函数 |
| Q10 | 客户州延迟率与有效样本数 | 分组聚合 |
| Q11 | 卖家排名、占比、累计占比 | `SUM() OVER(ORDER BY)` |
| Q12 | 卖家关联订单延迟率 | 先 `DISTINCT` 卖家-订单再聚合 |

### 2.2 口径处理

**销售金额以 `delivered` 为准。** 订单总数含全部状态，金额、运费、客单价只算已送达。金额缺失保持 NULL，不补 0。

**月度保留购买时间缺失组。** Q04、Q06 保留该组以便与总览对账；Q05 排除该组，且只在相邻日历月之间计算环比，前月缺失或为零时返回 NULL。首尾月份不参与峰值比较（前端月份订单量不足，末尾批次交付状态未成熟）。

**类别与卖家金额只纳入订单级金额完整的订单**，与 Q01 口径一致，保证可对账。类别运费比另用"商品、运费都完整"的配对样本，两个口径不混用。未知类别、地区、卖家保留在结果中。

**卖家履约先去重"卖家-订单"。** 一个订单含多个商品时按明细行聚合会重复加权；多卖家订单会同时归入多个卖家分组，所以卖家层面的延迟订单数不能相加当平台值。

**占比字段取 0–1 小数**，图表和报告转百分比。

### 2.3 执行与对账

12 条查询在数据库客户端（Navicat）依次执行，结果导出为一个含 12 个工作表加 1 个验收页的 Excel。执行前做了 11 项交叉对账：

订单键唯一、状态汇总等于总订单量、月度总订单量、月度已交付量、月度/类别/地区/卖家四处的商品金额、月度运费、地区已交付订单量、月度延迟有效样本。金额容差 0.01 BRL。四组不同粒度的商品金额都等于 13,221,498.11，四组才算通过。

图表与简报中的地区、类别排名另设展示门槛：至少 100 笔相关有效样本。这是展示条件，不是显著性标准，SQL 保留全量结果供复核。

## 3. 局限

1. 全部为描述性统计，不含因果推断。地区间延迟率差异混入了商品结构、卖家分布和距离因素，未做控制。
2. 类别与卖家的订单数是组内去重值，跨组不能相加；卖家延迟订单数不能相加当平台值，也不能归责到单个卖家。
3. 末尾月份的最新购买批次交付状态未成熟，不宜与其他月份直接比较。
